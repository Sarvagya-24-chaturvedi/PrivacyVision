01 · Overview

What is PrivacyVision?

PrivacyVision is an on-device visual perception engine and client-side privacy firewall built for autonomous Vision-Language Model (VLM) browser agents. It replaces traditional cloud-leaking browser extensions with an air-gapped zero-knowledge perception layer.

Traditional browser agents capture raw viewport screenshots and raw Document Object Model (DOM) trees and send them directly to cloud LLMs (such as GPT-4V or remote server endpoints). This exfiltrates passwords, banking credentials, two-factor codes, profile photos, and government identity cards to remote servers. PrivacyVision solves this by detecting and physically redacting all sensitive data inside client browser memory before network transmission.

02 · Core Architectural Novelties

Six Fundamental Differentiators

Core Novelty 01
Zero-Knowledge Perception
The remote VLM receives only a sanitized, blinded visual canvas containing interface geometry and labeled masks. Raw pixels never leave the client.
Core Novelty 02
Destructive Pixel Redaction
Executed on an isolated OffscreenCanvas using Canvas2D (Blackout, Blur, Mask). The original pixel bytes are replaced in memory, making reverse extraction mathematically impossible.
Core Novelty 03
Fail-Closed Privacy Firewall
An in-memory pre-flight outbound interceptor scans outgoing screenshots and node text. If any unredacted PII is detected, network serialization is immediately killed.
Core Novelty 04
On-Device Neural Models
MediaPipe BlazeFace ONNX running directly via WebGPU/WASM for real-time human face localization, combined with MobileViT scene classification.
Core Novelty 05
Statutory KYC Verification
Mathematical Verhoeff checksum algorithm for Indian Aadhaar verification, Luhn algorithm for payment cards, PAN cards, UPI IDs, and IFSC codes.
Core Novelty 06
Universal Page Coverage
Seamless support across standard HTML, Google Forms (cross-frame injection), Google Docs, PDFs, and Single Page Applications (MutationObserver).

05 · Literature Review & Comparison

Comparison Against Existing Literature

Existing literature in web agent automation focuses on benchmark performance while neglecting the acute privacy leakage inherent in multimodal screenshots:

  • Mind2Web (Deng et al., 2023): Benchmarks LLM reasoning over raw DOM trees. Transmits complete DOM hierarchies to remote models, lacking support for visual-only PII and offering no protection against credential exfiltration.
  • VisualWebArena (Koh et al., 2024): Supplies full-page screenshots to VLMs for visual grounding. Streams unredacted screens containing passwords, user avatars, and billing records directly to cloud APIs.
  • SeeAct (Zheng et al., 2024): Overlays Set-of-Marks visual tags onto raw screenshots for GPT-4V. Requires raw visual pixels to ground buttons, entirely compromising privacy during authenticated user sessions.
  • Enterprise Network DLPs (Symantec, Zscaler): Proxies inspect HTTP/TLS traffic on network gateways. Cannot parse rendered client-side canvases, SPAs, or encrypted WebSocket streams; cannot alter rendered pixel buffers.
  • Client Ad-Blockers (uBlock Origin): Intercepts network URLs via declarativeNetRequest filter lists. Only blocks tracking scripts; cannot parse visual scenes or assist browser automation.

Hard-Won Engineering Fixes

Bug #1 — Unredacted Anchor Node Text on Mailto Links (el-29)
Problem: dom-extractor.ts previously only sanitized .text for input and textarea tags. On links like <a href="mailto:...">, the inner text contained raw email addresses, causing the Privacy Firewall to rightly block the outbound request.
Fix: Extended node-text sanitization to all interactive elements (a, button, td, span) and added active regex sweep replacing any detected PII with [EMAIL_REDACTED] or [PHONE_REDACTED].
Bug #2 — Unchecked runtime.lastError Port Closure in Chrome MV3
Problem: In Manifest V3, when checkStatus() sent GET_STATUS while the service worker was waking up, uninspected lastError properties caused Chrome to flag red error badges in chrome://extensions.
Fix: Added explicit chrome.runtime.lastError checks to every message callback in popup.ts and consolidated duplicate message listeners in content-script.ts.
Bug #3 — Terminal & VSCode Closure Terminating Backend
Problem: Running uvicorn directly in a terminal killed the backend process upon closing VS Code or terminal due to SIGHUP termination signals.
Fix: Implemented permanent OS-level background services: macOS launchd user LaunchAgent, Linux systemd user service, and Windows Startup VBScript running silently via pythonw.exe.
Bug #4 — High-DPI Canvas Coordinate Scaling (DPR Blurring)
Problem: On Retina displays (devicePixelRatio = 2.0), physical screenshot pixel buffers did not align with CSS bounding boxes, causing offset redactions.
Fix: Injected window.devicePixelRatio into DOM extraction context and multiplied all bounding box dimensions by DPR inside the offscreen canvas redactor.
Bug #5 — Google Forms Shadow DOM & Iframe Barrier
Problem: Google Forms embeds input fields inside custom web components and iframes where top-level querySelector cannot reach them.
Fix: Configured all_frames: true in manifest.json, created frame-bridge.ts for subframe scanning, and added recursive shadowRoot traversal.
08 · Future Scope & System Blueprint

Future Scope & Engineering Roadmap

Roadmap 01
Edge SLMs in WebGPU
Porting 2B-3B reasoning models (Google Gemma-2 2B, Microsoft Phi-3.5 Mini) directly inside Chrome via WebGPU to remove external server dependencies completely.
Roadmap 02
Zero-Knowledge Proofs (zk-SNARKs)
Generating cryptographic proofs certifying that all detected PII was redacted according to enterprise policy without disclosing the underlying private data.
Roadmap 03
Differential Privacy on Tokens
Adding calibrated mathematical noise to intermediate visual embeddings to prevent neural feature inversion attacks.
